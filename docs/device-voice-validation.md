# On-device voice validation

The device implementation passed real CPU/WASM model inference in Chromium 153, plus 15 focused voice lifecycle checks and 15 general app browser checks. The final app/server suite passed 110 Node tests. These are local development results; a physical phone and the deployed Railway app have not been tested with this implementation.

## Real model evidence

`qa/device-voice-integration.mjs` runs the actual application, service worker, browser Cache Storage, local module worker, quantized Whisper `base.en`, and quantized Kokoro 82M. It uses a synthetic greeting generated by Kokoro as Whisper input. It does not acquire a microphone, mock inference, call an answering model, or use a paid API.

Two runs are recorded separately:

| Report | Installed pack | Evidence |
| --- | --- | --- |
| [device-voice-integration-results.json](device-voice-integration-results.json) | `studychat-device-voice-v1-1f4e2769bb9f98877d65`; 187,449,793 bytes | Five distinct non-silent voices; actual Whisper recognition; a 384-character reply speaks its ending; offline cached-shell reload and fresh worker synthesis. |
| [device-voice-final-pack-results.json](device-voice-final-pack-results.json) | `studychat-device-voice-v1-7b3d86f4313e4447da28`; **187,485,889 bytes / 178.80 MiB** | Final pack installation, model warmup, actual Heart synthesis and Whisper recognition, then offline cached-shell reload and fresh-worker Emma synthesis. Includes runtime, WASM, and ONNX SHA-256 hashes. |

The final pack has 20 verified assets. Expanded license notices changed its version and size; the models and inference runtime were unchanged. The final Heart WAV has exactly the same SHA-256 hash as in the five-voice run.

The worker initialized under the production content security policy. Whisper recognized “Hello, I would like to study today.” from actual Kokoro output. The longer answer exceeded the speech chunk size; a second real transcription recognized the final word “apple,” verifying that the ending was spoken. Every voice returned valid, non-silent PCM16 mono WAV at 24 kHz, with a different audio hash.

After installation, model/runtime fetches use the verified local pack. The browser observed two local module requests, `/voice-assets/runtime.js` and `/voice-assets/ort/ort-wasm-simd-threaded.mjs`; the service worker provides them from the completed cache. After destroying the engine, the test disabled the browser network, reloaded the cached app shell, created a new worker, and generated real speech successfully. Both real runs observed zero server speech API requests, external-origin requests, audio uploads, paid answering-model calls, and page errors.

## Observed speed

These are single measurements on the development host, using CPU/WASM with one ONNX thread. They do not estimate phone performance or voice quality.

| Operation | Observed time |
| --- | --- |
| Heart, 2.5 seconds of speech | 5.3 seconds |
| Bella, 2.9 seconds of speech | 6.0 seconds |
| Nicole, 3.4 seconds of speech | 7.0 seconds |
| Michael, 3.0 seconds of speech | 6.3 seconds |
| Emma, 2.8 seconds of speech | 5.9 seconds |
| Whisper recognition of the 2.5-second greeting | 3.5 seconds |
| 384-character answer, 26.7 seconds of speech | **54.4 seconds** |

The final pack smoke warmed both engines in 1.8 seconds; its offline reload, fresh warmup, and Emma generation took 7.5 seconds. Installation took 1.7 seconds over localhost; this measures local transfer and verification, not a user's download speed.

Long answers can require a substantial wait on CPU. The current engine prepares the complete reply before playback. It does not stream audio as tokens arrive.

## Browser lifecycle and app checks

[device-voice-browser-results.json](device-voice-browser-results.json) records 15 focused checks from `qa/voice-smoke.mjs`. This suite uses the real app, download integrity validation, Cache API, VAD, WAV capture processing, settings, and saved conversation behavior. Its worker inference, microphone hardware, playback, and answering provider are explicitly fixtures. It verifies:

- A compact black waveform control, five persistent labeled choices, and no microphone capture or model binaries downloaded at startup.
- Actual download cancellation, SHA-256 rejection of corrupt bytes, and successful retry. A download started in the compact header can finish while the voice dialog is already open, enabling Start without turning on the microphone.
- Permission denial preserves typed chat. One captured utterance invokes one local transcription, one answer using the selected Claude model, and one synthesis using the chosen Nicole voice. Retrying blocked playback reuses the prepared audio.
- Mute, Stop, closing, and backgrounding release capture resources. Background return does not resume capture. Deliberately late transcription and synthesis callbacks cannot submit an obsolete message or play obsolete audio; saved replies remain available.
- A 320-pixel viewport, reduced motion, and Escape cleanup.
- An interrupted v2 download preserves installed v1. After destroy/recreate, v1 works offline without fetching assets. Resuming the upgrade activates v2 and removes the previous model cache.
- Zero server speech API requests and no page errors.

[device-app-browser-results.json](device-app-browser-results.json) records 15 general browser flows from `qa/browser-smoke.mjs`, including typed streaming, model selection, cancellation, history, practice, review, cards, reference labels, settings, monitoring status, backup/restore, and the uninstalled-voice typed fallback. Its answering provider is a fixture.

## Reproduce

Build the pinned asset pack first if `public/voice-assets` is absent, using the procedure in the repository README. Supply an installed Playwright module and Chromium executable:

```sh
export PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright
export CHROMIUM_EXECUTABLE=/absolute/path/to/chromium

npm test
VOICE_RESULTS=docs/device-voice-browser-results.json node qa/voice-smoke.mjs
BROWSER_RESULTS=docs/device-app-browser-results.json node qa/browser-smoke.mjs
DEVICE_VOICE_RESULTS=docs/device-voice-integration-results.json node qa/device-voice-integration.mjs
DEVICE_VOICE_QUICK=1 DEVICE_VOICE_RESULTS=docs/device-voice-final-pack-results.json node qa/device-voice-integration.mjs
```

The scripts start their own local app with a temporary database and private test token. Reports contain no token or provider credential. The full real-model run includes all five voices and the longer reply; the quick run checks final-pack provenance, actual inference, and offline engine recreation.

## Remaining validation

Physical microphone permission, real human speech, accents/noise, medical vocabulary, speaker quality, Bluetooth routing, sustained phone memory/temperature/battery use, iOS installation, browser storage eviction, and deployment behavior remain untested. No human listening assessment or production latency guarantee follows from the synthetic round trip. Phone memory use was not measured.

Only recognition and synthesis operate offline after the pack is installed. New Coach answers still require the application's selected online OpenAI or Anthropic model and its configured limits. Their usage can cost money; local speech itself makes no paid speech calls. Installing a web app does not permanently protect its cached files from browser eviction.
