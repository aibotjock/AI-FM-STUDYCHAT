# Live guideline lookup

Typed chat and voice share the same gateway: supported selected models can perform hosted web search during a reply. No RAG, embeddings, index, extra backend service, or production npm dependency was added. Device Whisper and Kokoro remain on the device; the selected cloud language model handles reasoning and search.

Search is enabled by default. Set `WEB_SEARCH_ENABLED=false` to disable it. The UI shows whether the selected model supports search and explains that provider search fees apply. The model is instructed to search for uncertain clinical facts, changing recommendations and explicit verification requests, while answering ordinary conversation directly. Two provider tool calls per reply are permitted (OpenAI `max_tool_calls=2`; Claude basic `max_uses=2`). OpenAI's cap includes search/open/find operations; it is not a dollar or total input-token ceiling. Existing prompt, output, deadline, cancellation and single-active-request limits remain in place. Search results add provider input tokens and may increase latency.

Queries are restricted to official medical publisher domains listed in `server/web-search.js`: government/public-health agencies, professional guideline societies, NICE and WHO. These are a deliberate limited source set, not exhaustive coverage. Both API filters and citation URL checks enforce it. Retrieved pages are treated as evidence, never instructions; the prompt forbids patient identifiers in search queries. No new query/content telemetry is collected.

Actual provider search events show “Checking current sources…” in chat. Actual provider citation metadata produces clickable inline citations, source links, retrieval timestamps and saved source status. Claude citations must also match a retrieved result URL. Plain model-generated URLs and reference-directory links cannot become live-search citations. Search performed without a supporting citation, partial tool errors, and replies based only on model knowledge have distinct labels. If a completed lookup returns no supporting citation or a tool error, a streamed fallback tells the user it could not verify the guideline and to check in typed chat or the official guideline; the same text is passed to voice readout. Unsupported models receive an instruction to disclose unavailable lookup and direct guideline questions to typed chat with a search-capable model. There is no silent provider switch or paid retry. Provider `pause_turn` is reported as incomplete rather than starting another request automatically.

Citations establish provider-retrieved evidence, not independently verified clinical accuracy. The agent is instructed to check date, population, jurisdiction, superseded guidance and contradictions, and disclose uncertainty. Search does not prove that a full guideline was read, that it is the latest edition, or that it applies to a patient. Canonical practice grading remains on its existing deterministic path. Conversation history carries saved text, not provider-private encrypted search blocks; follow-up current guidance should be checked afresh.

Search can incur provider tool fees as well as token fees. For observed search requests, telemetry leaves total estimated cost unknown rather than reporting a text-only estimate as the total. Account access or organization settings can still reject a tool request; unsupported models continue to offer ordinary chat with explicit search-unavailable status.

Validation: deterministic provider fixtures cover native tool payloads and limits, allowlisted URLs, citation offsets, retrieved-source matching, failed lookup, `pause_turn`, disabled search, telemetry privacy and the spoken fallback. Browser fixtures cover lookup progress, inline links and saved history. These checks do not use real provider accounts or establish current clinical content accuracy. Live OpenAI/Claude searches and physical-device voice testing require the deployed update and account access.
